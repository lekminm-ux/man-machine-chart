DESIGN DECISION ALREADY MADE (do not re-litigate)
Module 5 currently only renders a column for an operator if they already
have at least one row (`ALL_WORKERS.filter(w => ... .length > 0)`). That
means an idle/underused operator has no column at all — no valid drop
target — which defeats the actual point of line balancing (moving work TO
someone with capacity). Claude's resolution: keep the normal (non-dragging)
view exactly as it is today — only show operators who already have work —
but while a drag is actively in progress, additionally render a lightweight
placeholder/empty column (dashed border, "no work yet" or similar, no bar
content) for every other `ALL_WORKERS` operator who currently has zero rows,
so they become valid drop targets for the duration of that drag only. These
placeholder columns disappear again once the drag ends (whether dropped
successfully, dropped invalidly, or cancelled). Implement exactly this, not
an always-visible full roster of 10 columns.

operator to another except manually editing the "Worker" dropdown in Module
1's own table — there is no way to do it directly from the Yamazumi chart,
which is where a user visually sees the imbalance they want to fix.
